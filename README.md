# tracking — 업무 트래킹 & 일정 관리

우선순위 정리, 프로젝트 데드라인 D-Day 확인, 캘린더를 한곳에서 보는 웹앱입니다.
빌드 도구 없이 순수 HTML/CSS/JS로 만들어져 GitHub Pages에 그대로 올라갑니다.

## 두 개의 앱

| | 경로 | 용도 |
|---|---|---|
| **조회 앱** | `/` | 읽기 전용 대시보드. 팀원·상사에게 링크를 공유합니다. |
| **입력 앱** | `/input/` | 내가 업무를 등록·수정하는 편집기. 내 컴퓨터에서 로컬로 돌립니다. |

입력 앱에서 편집한 내용은 자동으로 브라우저에 저장되지만, 그것만으로는 조회 앱에
반영되지 않습니다. 보고할 시점에 **게시**를 해야 공유 화면이 갱신됩니다.

## 쓰는 방법

저장소 폴더에서 **`업무입력.command` 를 더블클릭**하면 로컬 서버가 뜨고
브라우저에 입력 앱이 열립니다. (터미널에서 `node serve.js` 를 실행해도 같습니다.)

입력한 내용은 자동으로 브라우저에 저장되지만, 그것만으로는 조회 앱에 반영되지
않습니다. 보고할 시점에 오른쪽 위 **게시** 버튼을 누르면 그 한 번으로

1. `data.json` 을 저장소에 쓰고
2. 커밋하고
3. 푸시합니다.

푸시되면 GitHub Actions 가 자동 배포해서 **30초~1분 안에** 조회 앱에 반영됩니다.
상사·팀원은 링크를 새로고침하면 최신 현황을 봅니다.

버튼 왼쪽에 `● 로컬 게시 서버 연결됨` 이 떠 있으면 이 방식으로 동작합니다.
GitHub Pages 에서 입력 앱을 열면 로컬 서버가 없으므로 버튼이
`게시용 파일 내보내기` 로 바뀌고, `data.json` 을 내려받아 직접 올려야 합니다.

### 로컬 서버에 대해

`serve.js` 는 정적 파일을 서빙하면서 API 두 개를 제공합니다.

| | |
|---|---|
| `GET /api/status` | 로컬 서버 여부와 저장소 정보 |
| `POST /api/publish` | 받은 데이터를 `data.json` 에 쓰고 커밋·푸시 |

`127.0.0.1` 에만 바인딩하므로 같은 와이파이의 다른 기기는 접근할 수 없습니다.
푸시는 이 저장소에 설정된 SSH 키를 그대로 씁니다.

## 배포

Pages Source 는 **GitHub Actions** 이고, `.github/workflows/pages.yml` 이
`main` 에 푸시될 때마다 저장소 전체를 그대로 배포합니다. 설정할 것은 없습니다.

- 조회 앱 (공유용): https://mezemin.github.io/tracking/
- 입력 앱 (로컬로 쓰는 게 기본): http://localhost:8765/input/

> 입력 앱도 공개 URL이지만, 저장되는 데이터는 **접속한 사람의 브라우저 안에만**
> 남습니다. 다른 사람이 열어도 내 업무는 보이지 않고, 그 사람이 뭘 입력해도 내
> 데이터에는 영향이 없습니다. 공유 화면을 바꾸려면 저장소에 커밋할 권한이 필요합니다.

## 일정은 두 종류

| | 무엇 | 캘린더에서 |
|---|---|---|
| **프로젝트 일정** | 프로젝트 자체의 기간 (예: 농심 자판기 9/1~9/4) | 그 프로젝트 색의 **단색 줄** |
| **내 일정** | 내가 하는 개별 작업. 어느 프로젝트 것인지 고른다 | 같은 색이되 **끝부분(마감 지점)만** 칠해진 줄 |

프로젝트 줄은 한 달 내내 같은 행에 머물러 간트 차트처럼 읽힙니다.
기간이 여러 주에 걸치면 주 경계에서 각지게 이어집니다.

### 불타는 이펙트

프로젝트 마감이 **3일 이내**로 다가오면 (이미 지난 것 포함) 캘린더 줄과 프로젝트
카드에 불꽃이 붙고, 잔불 글로우와 열기가 훑고 지나갑니다. 프로젝트를 **완료**로
표시하면 꺼집니다. 임계값은 `shared/store.js` 의 `BURN_DAYS` 입니다.
`prefers-reduced-motion` 을 켠 사용자에게는 애니메이션 없이 정적인 글로우만 보입니다.

## 화면

**조회 앱**
- **우선순위** — 마감 임박도(마감 지남 / 오늘 / 3일 이내 / 이번 주 / 이후)로 묶은 목록. D-Day 배지, 진척률 바
- **캘린더** — 프로젝트 일정과 내 일정을 겹쳐 보는 월간 달력
- **프로젝트** — 프로젝트별 기간, 완료율, 다음 마감

**입력 앱** — 왼쪽에서 항목을 고르면 오른쪽에 해당 편집기가 열립니다.
- 프로젝트 일정: 이름 / 색상 / 시작일·마감일 / 완료 / 메모
- 내 일정: 제목 / 소속 프로젝트 / 우선순위 / 상태 / 진척률 / 시작일·마감일 /
  예상·실제 소요 시간 / 체크리스트 / 메모
- 백업 내보내기·가져오기

## 데이터 형식

`data.json` 한 파일에 모든 게 들어갑니다. 스키마는 [`shared/store.js`](shared/store.js) 참고.

```jsonc
{
  "version": 1,
  "publishedAt": "2026-09-02T09:00:00.000Z",
  "projects": [{
    "id": "...", "name": "농심 자판기", "color": "#e0533d",
    "startDate": "2026-09-01",        // 프로젝트 일정 시작
    "dueDate": "2026-09-04",          // 마감 — D-Day 와 불타는 이펙트 기준
    "done": false, "notes": ""
  }],
  "tasks": [{
    "id": "...", "title": "...", "projectId": "...",
    "priority": "high | mid | low",
    "status": "todo | doing | done",
    "progress": 0,                    // 0~100
    "startDate": "2026-08-24",        // 없으면 마감일 하루짜리
    "dueDate": "2026-08-28",          // D-Day 계산 기준
    "estimateHours": 8, "spentHours": 6,
    "notes": "...",
    "checklist": [{ "id": "...", "text": "...", "done": false }]
  }]
}
```

현재 올라와 있는 `data.json` 은 화면 확인용 **샘플 데이터**이며, 처음 게시하면
실제 데이터로 대체됩니다.

## 백업

입력 앱의 **백업 내보내기**로 언제든 전체 데이터를 파일로 저장할 수 있고,
**가져오기**로 되돌릴 수 있습니다. 브라우저 저장소를 지우면 데이터가 사라지므로
가끔 백업해 두는 것을 권합니다.

## 참고

`file://` 로 직접 열면 `fetch` 가 막혀 데이터를 못 읽습니다. 반드시
`업무입력.command` 나 `node serve.js` 를 통해 여세요.
